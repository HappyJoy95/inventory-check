# 门店库存盘点（扫码核对）

拉取云商 ERP 里指定门店仓的账面库存，用扫码枪扫 SN / IMEI 逐台核对，最后给出**未扫到**和**表外码**两张清单。

交付物是**一个文件**：`库存盘点.html`（双击用 Chrome / Edge 打开即可，不用装任何东西、不用起服务）。

---

## 一、使用流程

### 1. 打开并选择门店

双击 `库存盘点.html` → 页面自动读取仓库列表（本商家 45 个仓）。

- **盘点日期**：默认今天。这个日期是 ERP 的库存快照日，补盘以前的库存可以改日期。
- **筛选仓库**：输入关键字（如店名里的一个词）快速过滤。
- **仓库**：选择门店对应的仓（下拉里显示「仓库名（所属门店）」）。

点 **开始拉取库存**。一个门店几百行的账面通常 1 秒左右拉完。

### 2. 扫码盘点

进入扫码界面后，**光标自动停在扫码框里**，直接用扫码枪扫机器的 SN 条码或 IMEI 条码即可（扫码枪相当于键盘，自动回车提交）。

每扫一次，界面会立刻给反馈：

| 提示 | 含义 | 声音 |
| --- | --- | --- |
| ✅ **已盘到** | 本店账上有这台机器，标记为已盘 | 一声高音 |
| ↺ **重复扫描** | 这台机器之前已经盘过了（扫的是同一台的第 2 个串号也算） | 两声中音 |
| ⚠️ **非本店库存** | 本店账上没有这个码，但全公司别的仓有 → 会直接告诉你是哪个仓 | 两声低音 |
| ❌ **查无此码** | 全公司账面都查不到 → 可能扫错、条码破损或未入账 | 两声低音 |

- 手机有 IMEI1 / IMEI2 两个码，**扫到任意一个都算这台已盘到**。
- 扫串号时**大小写、空格都不影响**匹配。
- 扫码枪偶发连发两次同一个码，只算一次。
- 扫错了有三种撤销方式：
  - **撤销上一扫**（扫码台上的按钮）：撤销最后一条，可连点；
  - **撤销这一扫**（「已扫明细」每行右侧）：只删这一台的记录，其它扫码和手工确认都不受影响，撤销后它回到「未扫到」；
  - **最近扫描**列表里每条后面的 **✕**：删掉刚扫错的那一条；
  - 「表外码」页每行的 **删除这条**：删掉该码的全部扫描记录（含重复扫的）。
- 右侧实时显示：应盘 / 已盘到 / 未扫到 / 表外码 / 无串号商品 / 扫描总次数 + 进度条。

### 3. 盘完看结果 / 导出

下方五个标签页：

| 标签页 | 内容 |
| --- | --- |
| **未扫到** | 账面有串号但没扫到的机器（**盘亏嫌疑清单**）——商品名称、账面串号、分类、品牌、串号标识、商品编码；支持**手工确认**（见下）|
| **表外码** | 扫到了但本店账面上没有的码（**窜货 / 调拨未入账嫌疑**）——带归属仓库提示，可逐条写备注，也可**删除这条**（扫错时） |
| **已扫明细** | 盘到的每一台，含**来源**（扫码 / 手工确认）、扫到的码和盘点时间；**扫码的可以「撤销这一扫」、手工确认的可以「撤销确认」，都是逐条撤销、互不影响** |
| **在途待入库** | 账面已挂到本店、**货还没到**的在途商品（只在有数据时出现，取自库存表的在途列）。列出商品/串号/数量，状态标 **待入库**；如果货实际到了，直接扫它就会变成 **已扫到（货已到）** |
| **无串号商品** | 没有串号的配件、促销品等的**待办清单**（确认过的会自动移出）：列出账面数量，可**手工录入实盘数量**自动算差异，也可 **✓ 标记已找到** / **✓ 一键确认已填数量** 批量确认 |
| **手工确认** | 导出时单独一张表，列出所有人工确认过的机器 + 确认时间 + 原因备注，便于事后追溯 |
| **汇总** | 应盘 / 已盘 / 完成率 / 表外 / 差异等总账 |

右上角 **导出完整 Excel**：一次导出 **7 个工作表**（汇总、未扫到、表外串号、已扫明细、手工确认、无串号商品、账面全量）。也可以按页导出 CSV，或直接打印。

### 扫不了码的东西怎么办：两处「✓ 标记已找到」

**① 样机 / 演示机（有串号，但盒子找不到）** —— 在「未扫到」列表里：

1. 先在那一行的 **确认备注** 里写明原因（如「样机在展台，无盒」）；
2. 点 **✓ 标记已找到** → 这台立刻计入已盘，从未扫到清单消失；
3. 记错了？切到「已扫明细」，找到标着 <span>手工确认</span> 的那行，点 **撤销确认** 就回到未扫到。

列表右上角还有 **只看样机/演示机** 按钮，一键筛出串号标识带「样」的机器，盘点时先清这类。

**② 配件 / 促销品（没有串号，扫不了码）** —— 在「无串号商品」列表里：

- 点 **✓ 标记已找到** 表示「账面数量全在」：实盘数量自动等于账面、差异 0；
- **确认后这一行就从「无串号商品」列表移走**，进到「已扫明细」（来源标「手工确认」，扫到的码一列注明"无串号（账面 N）"）——所以这个列表就是个**待办清单**，越盘越短，标签页角标显示还剩几行；
- **数量有出入就直接改实盘数量**，系统自动算差异，不用先点按钮；
- 录数量时按 **Tab** 或 **回车** 直接跳到**下一行的实盘数量**（**Shift+Tab** 回上一行），一路填到底不用碰鼠标；填到最后一行再按 Tab 会回到扫码框接着扫码；
- 填完一批可以点工具条上的 **✓ 一键确认已填数量（N）**：把所有**已经填了实盘数量**的行一次性确认（会弹窗确认一次，N 就是会提交的行数）；**没填数量的一行都不会动**，避免把没盘的当成盘过了；
- 按钮上的 **N 是实时跟着你填的数量走的**（填一行就 +1，清空就 -1，全空时按钮置灰），不用切页刷新；如果用了搜索筛选，**只提交筛选出来看得见的行**；
- 点错了在「已扫明细」里找到那一行点 **撤销确认**，它就回到「无串号商品」待办列表（数量是确认时自动带出的会一起清掉，你自己手填的数量会保留）。
- 列表上方有一行进度：`共 35 行，已确认 3 行，列表里还剩 32 行待确认，其中 2 行已填数量可一键提交`。

配套的口径：

- 统计卡片和汇总里，**已盘到 = 扫码盘到 + 手工确认**，两者分开计数，不会混（「其中手工确认」只算有串号的机器，无串号商品的确认单独按"已手工盘过行数"统计）；
- 手工确认过的机器如果后来又被扫到码，会自动升级成「扫码盘到」（备注保留）；撤销那次扫码，手工确认状态会恢复；
- 导出的 Excel 里：「已扫明细」有**来源**列；「手工确认」表带**类型**列（有串号 / 无串号）+ 确认时间 + 原因，是人工判断的完整留痕；「无串号商品」表有**是否确认 / 确认时间**列；「账面全量」的**盘点方式**列区分 扫码盘到 / 手工确认 / 无串号·已确认 / 未扫到 / 无串号。

## 二、续盘与安全

### 每次盘点都会把「账面」冻结在本地

点 **开始拉取库存** 时，程序会把这一版账面（商品、串号、数量、分类属性）**完整存到本机**，并记录：

- 会话编号、仓库、盘点日期、账面版本号、**账面实际拉取时间**；
- 每条账目的**会话内唯一标识（uid）**：有串号的按串号生成，无串号的按 `仓库+商品编码+完整分组属性` 生成；
- 扫码流水、手工实盘数量、手工确认时间、备注。

之后**扫码、手工确认、实盘数量、备注全部按 uid 关联**，不再使用报表行号。所以：

- 库存有增删、行号整体位移，**A 机的数量和确认状态不会跑到 B 商品上**；
- 续盘时**只读本地账面**，不再回头拉 ERP —— **断网、token 过期都能继续盘点、继续导出**；
- 即使一次码都没扫（只做了手工确认 / 只写了备注），会话照样能恢复。

### 在途（待入库）怎么算

在途**就从盘点用的那张自定义库存表里取**，不用额外的接口：

- 请求时 `outCol` 同时取 `ProCount`（在库数量）和 **`ProCount_OnTransfer`（在途数量）**——列名来自报表列配置接口 `/Api/RoleMenu/RoleRptCol`（RptId=100 就是这张库存表），ERP 前端在查"今天"时会保留这列、查历史快照日才把它剔掉；
- 拆分规则（**在库配在库、在途配在途**）：
  - 本店在库为 0、在途 > 0 → 整行算在途，成一条在途账目；
  - 本店在库 > 0、在途 > 0、**无串号**（配件这类按数量管的）→ **拆成两条**：在库那条留在「无串号商品」按实盘数量核对，在途那条单独进「在途待入库」，两边各算各的（uid 分别是 `ns:` 和 `nst:`，不会互相覆盖）；
  - 本店在库 > 0、在途 > 0、有串号 → 业务上不会出现；真出现以在库为准，在途数量仍保留在账面里（导出可见），不会生成重复条目；
- 这些行进账面、单独放在 **「在途待入库」页签**，状态标 **待入库**，并带出串号；
- **不混进"必须扫到"的口径**：应盘、未扫到、盘点进度都只算在库的商品——货还没到店，本来就不该被当成漏盘；
- **口径不互相污染**：无串号商品的实盘差异只对"在库"那条算，在途那部分不进差异（否则天天显示盘亏）；汇总里账面数量拆成「在库 / 含在途」两个数；
- 货实际到了就直接扫它：会命中（不是"查无此码"），该条变成 **已扫到（货已到）**，并出现在「已扫明细」；
- 导出里：「在途待入库」独立一张表，汇总有「在途（待入库）台数 / 其中已扫到（货已到）」，账面全量的**盘点方式**列区分 `在途待入库` / `在途·已扫到`。

> 如果某天这张表没给在途列（例如查历史快照日、或商家配置不同），程序会自动改用 ERP 的库存明细接口（`Api/Report/InventoryImei` + `InventoryType=1`）兜底一次；两条路都拿不到时**不影响在库盘点**，只在提示里明确说明「在途未拉到」，顶栏也会显示。可以在设置里关掉整个在途查询。

### 保存与失败处理

- 每次扫码、手工确认、改实盘数量、写备注都会**立即写入本机**（不是等关闭才写），界面右上角显示 **已保存 hh:mm:ss**；
- 保存失败（本机存储空间不足、浏览器禁用存储）会**明确红字提示**，并把 **下载会话备份** 按钮标红 —— 备份是一个 JSON 文件（含账面 + 全部记录），换台机器也能凭它恢复；
- **结束本次盘点** 前会先提交正在编辑的内容，并**取消尚未执行的保存任务**，不会出现"清空之后数据又被写回来"。

### 换机器 / 没盘完接着盘：加载未完成盘点

开头（设置区）就有 **加载未完成盘点** 按钮：选一个之前导出的**会话备份 JSON**，就能接着上次的进度继续盘——
账面、扫码记录、手工确认、实盘数量、备注、在途清单全部回来，**不需要登录、不需要联网**。

什么时候用：

- 盘点中途换了一台电脑 / 换了浏览器；
- 清了浏览器数据、或者本机存储写满被迫换地方；
- 别人盘了一半，把文件发给你接着盘。

导出的入口有两个：扫码台工具条上的 **下载会话备份**，以及保存失败时被标红的同一个按钮（那时它是保命通道）。
备份文件里含完整账面与全部记录，**当心隐私**，别随手发到群里。

### 需要更新账面时（独立操作）

盘点中发现账面不对（ERR 里刚调拨、刚卖掉），点 **更新账面**：

1. 重新拉取一次库存（这一步会校验数据完整性，拉不全直接报错、**不会用半份账面对付**）；
2. 弹出**差异评审**：新增 X 条 / 移除 Y 条 / 数量变化 Z 条 / 不唯一 W 条，并列出明细；
3. 确认后才建立**新账面版本**（旧账面自动保留为「上一版」，可回滚）。

应用时的继承规则：

- 扫码记录：**按串号重新核对**（串号稳定，安全）；
- 手工实盘数量 / 手工确认 / 备注：只保留在**两版都唯一对应**的条目上；
- 账面里同一商品有多条（匹配不唯一）或商品已被移除的手工记录，一律进入 **「待核实」** 页签，**不自动继承**，由人工处理。

### 旧版本记录怎么处理

旧版本没有保存原始账面，无法保证手工记录与当前商品对应。程序的做法是：

- 先把旧记录**完整备份**在本机（不删原数据）；
- 扫码记录**按串号重新核对**（安全）；
- 手工数量、手工确认、备注**全部列入「待核实」**，人工核对后才算数。

### 登录与凭证（首次使用必读）

**本工具不含任何内置账号、token 或商家编码**，不会用别人的身份拉数据。首次使用请：

1. 点 **接口设置** → 展开「账号密码登录」（首次打开会自动展开）；
2. 填入**你自己的** ERP 账号 + 密码 → 点 **登录并更新 token**；
3. 程序用账号换到 token，再自动调 `Api/User/UserIndex` **带出商家编码和用户名**——所以你不用知道 companycode，也不用手工复制 token。

之后：

- **默认只保存 token，不保存密码**。token 有效期内打开就能直接用；
- token 过期（或换电脑、清了浏览器数据）时，页面提示**重新登录**，输一次密码即可；
- 想让它**自动续期**，才需要勾「记住密码」——密码以明文存在本机浏览器（只在本机可见、不会上传），token 过期时自动重新登录，门店不用管。公用电脑请保持不勾选，事后可点「清除已保存密码」。
- 已经手工拿到 token 的话，把 token 粘到「登录 token」框，点 **用下面的 token 验证**，程序同样会自动带出商家编码。

> 运维提示：**从代码里删掉 token 不等于作废它**。已经分发出去的旧版本里内置过的 token，必须在 ERP 里退出登录 / 改密码 / 由管理员重置，让它真正失效。

## 三、常见问题

**扫码枪扫了没反应？**
先用鼠标点一下页面空白处（焦点会自动回到扫码框），确认扫码枪是「键盘模拟」模式并且带回车后缀。若扫码枪只发 Tab 不收尾，本工具同样支持 Tab 提交。

**提示"登录已过期"怎么办？**
展开「账号密码登录」，填一次 ERP 账号密码点登录即可；以后过期会自动重新登录。若提示需要验证码，照图输入。若提示"用户名或密码错误"，说明 ERP 密码改过了，重新填新的密码。

**「表外码」只提示"本店账面没有"、不显示归属仓库？**
归属提示依赖「全库串号索引」，它在拉完库存后于后台自动建立（全公司 2.6 万行、约 1.1 万个 15 位 IMEI，耗时 10~20 秒）。可看顶栏的「全库索引」状态，或点接口设置里的 **立即加载全库索引** 手动触发。

**无串号商品为什么不参与扫码？**
像「促销品七合一清洁套装 ×100」这类商品账面只有数量、没有串号，扫不了码。它们单独列在「无串号商品」页，人工清点后在实盘数量列填数字，系统自动算差异。

**盘点日期该怎么选？**
正常盘点保持今天即可。ERP 的这个字段是库存快照日，选历史日期会返回那一天的账面库存，适合事后补盘对账。

## 四、技术说明（维护用）

### 数据来源

页面直接调用 ERP 的 JSON 接口（接口会回显请求 Origin，所以本地 `file://` 打开也能直接调）：

| 用途 | 接口 |
| --- | --- |
| 仓库列表 | `POST https://apicommon.yserp.cc/API/USER/STORE` |
| 库存明细 | `POST https://apireport.yserp.cc/api/supplier/RptStoreNow` |
| 账号登录换 token | `POST https://api.yserp.cc/api/User/Login`（表单参数 `token=''`、`userName`、`userPwd`、可选 `VCode`） |

请求头需要 `Authorization: Bearer <token>`、`companycode`、`username`。库存接口用 `StoreIds=<仓库Id>` 过滤门店，`DateOfSnapshot` 指定快照日，`PageSize` 一次可拉全量（返回 `Data.TotalRows` 做校验）。

字段对应：`Imei` = 串号1、`Imei2` = 串号2、`Imei3` = 串号3、`SubImei` = 三个串号空格拼接（作为兜底串号来源）、`ProId` = 商品编码、`SNCode` = 69码、`ProCount` = 在库数量。

登录契约：成功时 `ResponseID=0`、`Data.token` 就是后续要用的 token；需要验证码时 `ResponseID=2`、`Data` 直接是 `data:image/png;base64,...` 图片（**不依赖 cookie**，所以跨域静态页也能走通）；token 失效时任何接口都返回 `ResponseID=1 未登录或登录超时！！！`，程序据此用保存的账号密码自动重登并重试一次。

> 注：ERP 自带的「导出」接口 `/api/export/ExportRptStoreNow` 生成的 xlsx 存放在 `file.yserp.cc`，该域名**没有 CORS 头**，浏览器读不到，所以本工具走 JSON 接口而不是下载 Excel。

### 本地存储结构

| 键 | 内容 | 何时写 |
| --- | --- | --- |
| `ic.cfg.v2` | 接口配置（token、商家编码、用户名、偏好） | 登录 / 改设置 |
| `ic.book.v2` | **冻结账面**（会话号、仓库、日期、版本、拉取时间、全部账目） | 开新盘点 / 更新账面 |
| `ic.book.prev.v2` | 上一版账面（更新账面时自动留档，可回滚） | 更新账面 |
| `ic.state.v2` | 可变状态（扫码流水、实盘数量、确认、备注、待核实） | 每次操作立即写 |
| `ic.legacy.v1` | 旧版本记录的备份 | 迁移时 |

账面与状态分开存的原因：账面可能是几百 KB～1MB 但一次盘点里不变，状态很小但每次操作都要写；
合在一起会导致"每扫一次码就序列化并写入 1MB"。实测 localStorage 上限约 4.75MB，写满会抛 `QuotaExceededError`，界面据此提示并引导下载备份。

### 拉取完整性校验

拉库存（和全库索引）必须**完整**才允许开始盘点，以下情况一律报错并阻止：

- 响应结构不对（`Data` 不是对象、`Data.Data` 不是明细数组、`TotalRows` 不是数字）；
- `ResponseID` 不是 0（与 ERP 前端一致，只有 0 算成功）；
- **实际行数与 `TotalRows` 不一致**（这是"应有 3 行只收到 1 行"必须被拦住的关键）；
- 分页途中**提前返回空页**、**返回重复页**、**`TotalRows` 中途变化**、**达到分页上限仍没拉全**、**返回行数超过总数**。

合法的零库存（`TotalRows=0` 且没有明细）算成功。失败时会保留当前会话，**不会用半份账面替换**已有账面。

### 回归夹具：仓库里只放合成数据

- 仓库自带 **合成夹具** `test/fixtures/synthetic-*.json`：结构与真实抓取完全一致（行列数、串号个数分布、有/无串号比例），但商品名和串号都是生成的，**不含真实门店信息**；用 `node tools/make-synthetic-fixture.mjs` 可重新生成（固定种子，结果可复现）。
- **真实夹具不入库**：`.gitignore` 排除了 `test/fixtures/*.json`，只放行 `synthetic-*.json`。用 `node test/live.test.mjs --write-fixture` 抓下来的真实账面只留在本机。
- 夹具发现规则：取 `test/fixtures/` 里**最近修改**的那一份——所以本机刚抓过真实数据时会自动用它，clone 下来则用合成的那份。
- `test/live.test.mjs` 默认**不会覆盖夹具**，要写必须显式加 `--write-fixture`。

生产联调需要的门店也从环境变量来，仓库里不留真实店号店名：

```bash
ERP_TOKEN=xxx ERP_COMPANYCODE=yyy ERP_STORE_ID=仓库Id ERP_STORE_NAME=仓库名 npm run test:live
ERP_TOKEN=xxx ERP_COMPANYCODE=yyy ERP_STORE_ID=仓库Id npm run test:e2e
```

构建时会做**凭证守卫**：源码或产物里出现 token 形态（32 位 hex）、`Bearer` 字面量、写死的商家编码/中文用户名等，构建直接失败；`npm test` 里也有一条断言，并用假凭证验证守卫本身确实拦得住。

### 已验证的行为

交付物检查、身份隔离、会话与账面、拉取完整性、完整流程，全部有**离线可重复**的自动化断言（`npm test`，不联网、不需要凭证）：

- **凭证**：全新浏览器打开成品向 ERP 发出的请求数 = **0**；源码/产物/测试文件均不含账号凭证；构建守卫用假凭证自测能拦住；
- **身份与账面**：行号重排 + 新增一行 + 移除一行之后，扫码记录、手工确认、实盘数量、备注仍跟着原商品走，不会平移到别的商品；匹配不唯一的条目禁止自动继承；
- **续盘**：把「冻结账面 + 已盘记录」塞进本地存储后打开页面，**0 个网络请求**完成恢复，能继续扫码、继续导出；只做了手工确认或只写了备注的会话同样能恢复；
- **保存**：扫码/手工确认后 **150ms 内**已写入本机；存储配额不足与被禁用时抛出明确错误（含"空间不足"提示），不会静默丢数据；
- **更新账面**：能识别新增/移除/数量变化/不唯一四类差异并列出明细；
- **拉取完整性**：应有 3 行只收到 1 行、提前空页、重复页、总分页数变化、分页上限、非法零库存等全部阻断并说明原因；
- **端到端**（离线，用页面内桩顶替 ERP）：开新盘点 → 冻结账面 → 扫码 → 立即落盘 → 刷新 → **不重新拉库存**地续盘 → 导出 → 结束盘点清键；
- **索引隔离**：甲仓开始加载索引（接口故意慢 4 秒）后切到乙仓，甲仓的索引晚返回时被丢弃 —— 乙仓不会被贴上归属，只会提示"本店账面没有该码，归属尚未核实"；乙仓自己重新加载后归属才生效；
- **逐条撤销**：撤销某一条扫码后只影响那一台（已盘数 -1、该商品回到「未扫到」、其它记录与手工确认不受影响）；同一码扫两次时删掉「已盘到」那条，剩下那条会顶上仍是已盘；表外码可整条删除；「最近扫描」的 ✕ 只删那一条；
- **加载未完成盘点**：全新浏览器（未登录、无网络）加载会话备份后，账面/扫码/手工确认/实盘数量/备注全部恢复且 0 网络请求，能继续扫码；非 JSON、别的 JSON、缺账面的文件都给出明确错误；
- **在途待入库**：在途取自库存表的 `ProCount_OnTransfer` 列（同表，不额外请求；拿不到才走明细接口兜底）；无串号商品"在库 10 + 在途 5"会拆成两条且互不干扰，差异只对在库那条算、不计入应盘/未扫到/进度、别仓的在途被过滤、到货扫到后变「已扫到（货已到）」并进已扫明细、导出有独立工作表与汇总口径；在途接口失败时在库盘点照常且提示明确；
- **旧版迁移**：本机只有旧版记录时，先保留备份 → 重建账面 → 扫码按串号核对回来 → 手工数量/确认/备注 3 条全部进入「待核实」页签并写明原因，迁移后仍可正常扫码；
- **保存失败**：模拟存储写满时，状态栏红字提示"本机存储空间不足"、备份按钮标红、扫码功能不受影响、下载的备份里含完整账面与记录；一直失败也仍能干净地结束盘点；
- **网页托管形态**：把产物托管在真实的 http 来源 + 子路径下（与 Pages 的项目站点 URL 同形）打开，启动/拉仓库/拉库存/冻结账面/扫码落盘全部正常、localStorage 可用、0 个 JS 报错；并断言 `index.html` 与 `库存盘点.html` 逐字节相同（线上版本 = 线下发出去的版本）。

需要真实 ERP 的联调单独跑，凭证从环境变量提供：`npm run test:live` / `npm run test:e2e`。
